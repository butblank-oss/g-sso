# iOS vs 안드로이드 기준

같은 앱이라도 OS와 만나는 화면은 다르게 움직인다. **OS와 만나는 화면은 iOS와 안드로이드를 따로 설계하고 따로 확인한다.**

- 1절: 레퍼런스 릴스(@qaonetop "iOS와 안드로이드 차이점", iOS 26 / 안드로이드 15 이후 기준)
- 2절: 플랫폼 디자인 가이드(Apple HIG, Material Design)의 기본 규칙 (스킬 보강용)

## 1. OS와 만나는 화면 8가지 (릴스 내용)

| 화면 | iOS | 안드로이드 | QA 체크 |
|---|---|---|---|
| 뒤로 가기 | 왼쪽 가장자리를 밀기 (+ 왼쪽 위 ‹) | 시스템 제스처 또는 하단 ◁ 버튼 (설정에 따라) | 제스처와 버튼, 두 방식 모두 같은 화면으로 가는지 |
| 위치 권한 팝업 | 한 번 허용 / 앱 사용 중 허용 / 허용 안 함, 지도 미리보기와 '정확한 위치' 켜고 끄기 | 정확한 위치 / 대략적인 위치를 먼저 고르고, 앱 사용 중에만 허용 / 이번만 허용 / 허용 안 함 | '한 번만(이번만) 허용'을 고르면 다음에 다시 묻는지 |
| 알림 권한 | 처음 한 번 시스템 팝업으로 물어봄 | 안드로이드 13 이상만 팝업으로 물어보고, 12 이하는 설치하면 바로 켜짐 | 안드로이드 13 이상과 그 아래 버전을 나눠서 확인 |
| 키보드 | 기기마다 높이가 다름 | 기기와 키보드 앱(삼성, Gboard 등)마다 높이가 다름 | 안드로이드 15 이상(전체 화면 강제)에서 저장 버튼이 키보드에 가려지지 않는지 |
| 날짜 선택 | 달력 또는 휠 (인라인/팝오버) | 달력 창(다이얼로그) | 고른 날짜가 두 OS에서 같은 형식으로 저장되는지 |
| 공유 창 | iOS 공유 시트 (아이콘 □↑) | 안드로이드 공유 시트 (아이콘 <) | 공유한 링크가 받은 쪽에서 제대로 열리는지 |
| 기본 글꼴 | SF Pro / Apple SD Gothic Neo | Roboto / Noto Sans CJK, 제조사 글꼴(삼성 One UI 등) | 같은 문구도 줄바꿈이 달라져서 긴 문구가 잘리거나 넘치지 않는지 |
| 결론 | | | OS와 만나는 화면은 iOS와 안드로이드를 꼭 따로 확인 |

## 2. 설계 기본 규칙 (플랫폼 가이드 기준)

| 항목 | iOS | 안드로이드 |
|---|---|---|
| 최소 터치 영역 | 44 × 44pt | 48 × 48dp |
| 상단 제목 | 가운데 정렬, 목록 첫 화면은 큰 제목(Large title) | 왼쪽 정렬 (Top app bar) |
| 뒤로 가기 버튼 | ‹ + 이전 화면 이름 | ← 아이콘만 |
| 하단 메뉴 | 탭 바 (아이콘 + 라벨) | 내비게이션 바 (선택 탭에 알약 모양 표시) |
| 주요 행동 버튼 | 화면 하단 고정 버튼 또는 상단 오른쪽 텍스트 버튼 | FAB 또는 하단 고정 버튼 |
| 확인 창 | 알림창(Alert): 가운데 정렬, 취소 왼쪽 · 확인 오른쪽, 위험한 행동은 빨간 글자 | 다이얼로그: 왼쪽 정렬 제목, 버튼은 오른쪽 아래 텍스트 버튼 (취소 → 확인 순) |
| 선택지 여러 개 | 액션 시트 (아래에서, 취소 따로) | 바텀시트 또는 메뉴 |
| 짧은 알림 | 시스템 토스트 없음 → 앱 안 배너나 HUD로 만듦 | 시스템 토스트 / 스낵바 |
| 스위치 | 초록 둥근 스위치 | Material 스위치 (썸에 체크 아이콘 가능) |
| 화면 아래 영역 | 홈 인디케이터 위 여백(Safe area) | 제스처 바 또는 3버튼 내비게이션 바, 안드로이드 15부터 앱이 그 아래까지 그려짐(edge-to-edge) → 여백 직접 확보 |
| 당겨서 새로고침 | 목록 위에 스피너가 생김 | 원형 인디케이터가 위에서 내려옴 |
| 스크롤 끝 | 고무줄처럼 늘어났다 돌아옴(Rubber-banding) | 늘어나는 효과(Stretch overscroll) |
| 진동 피드백 | 햅틱(성공·경고·선택) 세분화 | 기기마다 품질 차이가 커서 최소한으로 |
| 앱 아이콘 | 둥근 사각형, OS가 자동으로 깎음 | 적응형 아이콘(모양은 기기마다 다름), 테마 아이콘 대응 |

## 3. 스킬에서 쓰는 법

1. **확인 단계에서 대상 플랫폼을 묻는다:** iOS / 안드로이드 / 둘 다 / 웹(모바일).
2. **둘 다**라면 위 표의 항목이 들어가는 화면은 추천 표에 `iOS | 안드로이드` 두 열로 따로 적는다.
3. 프로토타입이 웹 하나로 만들어질 때는 OS 차이가 나는 부분에 표시를 남긴다 (예: "안드로이드는 시스템 토스트, iOS는 앱 배너").
4. 마무리 점검에 1절의 QA 체크 8개 중 해당 화면 항목을 넣는다.
5. 공통으로 맞출 것: 브랜드 색, 글자 크기 체계, 문구, 아이콘 스타일. 다르게 맞출 것: 내비게이션, 시스템 팝업, 확인 창, 피커, 공유, 하단 여백.
