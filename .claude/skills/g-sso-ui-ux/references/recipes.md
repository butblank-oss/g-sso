# 화면별 추천 조합

각 항목: **기획 → 디자인 → 프론트** 순서. 그대로 추천 표에 옮겨 쓴다.

## 회원가입 / 로그인
- 기획: 간편 로그인 우선, 약관 동의는 필수/선택 분리(선택 항목 미리 체크 금지)
- 디자인: 라벨(플레이스홀더만 쓰지 않음), 비밀번호 강도 표시기, 생년월일 데이트 피커
- 프론트: 인라인 에러(팝업 금지), 가입 버튼 비활성 → 로딩 → 성공 상태
- 프롬프트: "이메일 칸은 라벨 고정, 틀리면 인라인 에러로, 비밀번호엔 강도 표시기, 생년월일은 데이트 피커로"

## 온보딩 / 첫 실행
- 기획: 스플래시 → 온보딩(3장 이내) → 권한 요청(필요한 순간에) → 웰컴 화면
- 디자인: 페이지 인디케이터, 첫 사용 빈 화면에 행동 하나
- 프론트: 첫 데이터 로딩은 스켈레톤, 코치마크는 1회만

## 목록 / 피드
- 기획: 빈 화면(첫 사용·검색 결과 없음·필터 결과 없음·오프라인), 끝에 "모두 완료" 멈출 곳
- 디자인: 카드 vs 리스트 선택, 고정 헤더, 필요 시 FAB
- 프론트: 스켈레톤 로딩, 당겨서 새로고침, 무한 스크롤 vs 페이지네이션 결정, 밀어서 삭제 + 스낵바 되돌리기

## 저장 / 삭제 / 피드백
- 저장: 토스트 2초
- 삭제: 스낵바(되돌리기)
- 되돌릴 수 없는 결정: 모달 · 선택지 고르기: 바텀시트

## 후기 / 평가
- 기획: 짧게 받기(별점 + 평가 태그), 추천 의향은 NPS
- 디자인: 평점 요약(평균 + 분포), 목록에는 평점 배지
- 프론트: 반 별점 표시 여부, 이모지 평가는 1탭 완료

## 완료 / 성취
- 작은 일: 체크 그리기, 할 일 줄긋기, 버튼 모핑
- 중간: 진행률 완료, 스탬프, 보냄 애니메이션
- 큰 일: 배지 획득, 컨페티, 완료 화면

## 결제 / 구독
- 기획: 다크패턴 9종 점검(숨은 비용·몰래 자동 결제·숨은 해지 특히), 해지는 가입만큼 쉽게
- 디자인: 최종 금액 한 화면에 모두 노출, 무료 체험 남은 기간 명확히
- 프론트: 결제 버튼 로딩/오류 상태, 중복 클릭 방지

## AI 기능 화면
- 생각 중 표시 → 스트리밍 답변 → 출처 표시 → 답변 피드백
- 입력부: 추천 질문 칩, 파일 첨부, 고쳐 묻기, 다시 생성
- 긴 작업: 에이전트 단계 표시

## 랜딩 / 소개 페이지
- 레이아웃: 히어로 → 벤토 그리드 또는 카드 그리드 3열 → Z 패턴 기능 소개 → 풀블리드 CTA
- 모션: 순차 등장, 숫자는 카운트 업, 헤드라인은 페이드 업 또는 단어 교체
- 스타일: 스타일 이름 하나로 지정(미니멀, 글래스모피즘 등)

## 대시보드 / 어드민
- 레이아웃: 사이드바 레이아웃 + 대시보드 카드
- 내비게이션: 브레드크럼, 상단 탭
- 입력: 셀렉트, 세그먼트, 범위 슬라이더, 데이트 피커 (QA 검증 포인트 함께 적용)

## 모션 기본값
- 들어오는 요소: 이즈 아웃 / 나가는 요소: 이즈 인
- 손으로 다루는 요소(시트, 카드): 스프링
- 목록: 순차 등장 / 상세로 이동: 카드 확장 또는 공유 요소 전환

## 모션 품질 규칙 (꿀렁임 방지)
- 바텀시트·모달: 들어올 때 감속 곡선 `cubic-bezier(.32,.72,0,1)` 0.35~0.4s, 나갈 때 가속 곡선 `cubic-bezier(.4,0,1,1)` 0.2~0.25s. **오버슈트(튕김) 금지.** 스프링은 손으로 끄는 경우에만 쓴다.
- 화면 밖에 있는 요소에 `focus()`를 주지 않는다. 등장이 끝난 뒤 `focus({preventScroll:true})`로 준다. 그러지 않으면 브라우저가 뒤 화면을 끌어올려서 출렁인다.
- 닫힌 시트는 `visibility:hidden`으로 숨겨 포커스·탭 이동을 막고, 닫으면 포커스를 연 버튼으로 돌려준다.
- 움직임은 `transform`과 `opacity`만 쓴다 (`top`·`height`·`margin` 애니메이션 금지).
- 다시 그릴 때 값이 0부터 다시 차오르지 않게 이전 값에서 이어서 움직인다 (진행률·숫자).
- 튕김을 쓰는 곳(스위치, 배지)도 오버슈트는 작게(1.2~1.25).
- `prefers-reduced-motion`이면 애니메이션을 끈다.

## UX 문제 검증 요청 시
퍼널 분석(어디서) → 사용자 인터뷰(왜) → A/B 테스트(확인). 메뉴 구조 문제면 카드 소팅·트리 테스트, 행동 위치는 히트맵.
